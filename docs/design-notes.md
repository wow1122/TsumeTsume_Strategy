# 作者の言葉と残す学び

仕様ではなく、作品の考え方の記録。作者の言葉は原文のまま残す（書き直さない）。

## メモリという名前の由来

**メモリという名前の由来**（2026-10-24 作者談）: 「技の値が高い、つまり技術があったり手先が器用な人ほど
脳のメモリが大きく（広く？）、扱いの難しい武器を使いこなしたり大技を発揮するのが得意だ」という、
作者の人間観察からきた経験則。**初期値＝技**はこの発想の反映。フェイズごとに少しずつ増えるのは、
スポーツやゲームや仕事に取り組むとき、開始から時間が経つにつれて徐々にパフォーマンスを発揮したり
集中や高揚に至ったりしやすい、という作者の実感から。この世界の住人も気持ちの在り方や意識の覚醒の仕方が
それに近いという想定で、ゲームが進むにつれて徐々に脳のメモリが解放されるイメージ。
実装との対応: 技が効くのは「最初から空いているメモリの量」（初期値）で、上限は全員同じ（1本30・2本まで）。
解放の速さ（フェイズごとの上昇量）は魔力で決まる。どちらもゲームバランスを考えた設定だが、
難易度やゲージを本格的に活用できる環境は、物語本編のマップの製作時に考える（作者方針。今のマップは検証用）

## 輸送隊の世界観

補給の仕組みは 2026-10-24 に撤廃したが、作者の文言としてそのまま残す。

**世界観**（局地戦なので「兵站」ではなく人の往復で説明する）:
輸送隊は部隊自身の装具一式を積んだ荷駄。従者が前線と荷駄を馬に乗って往復し、傷んだ得物を替えている。
だから距離が関係し、敵に道を塞がれると往復できなくなり、山や城壁は越えられない。
用語は **陣中／孤立**、武器の状態は **傷んでいる**。

## 残す学び

- probe（状態をお試しで切り替えて評価し、finally で必ず戻す）は、`WeaponChoiceRules` のお試し装備で使っている。
  `Unit.Equip` / `Unequip` に副作用を足さない約束はそのまま
- 1つのプロパティを状態によって値の変わる窓口にすると、別の状態を前提に測っていた読み手だけが壊れる
  （2026-08-10 の `Unit.Move`。窓口化したら全読み手を grep して1件ずつ確かめる）
- 制限を緩めるときは、その制限を前提にしていた全分岐を見直す（2026-07-30 の引き受け後の飛翔）
- 敵AIの行動順は名簿順＝ステージの配置順で、機能どうしの噛み合わせを決める（2026-08-05 の撃墜で分かった）
- 武器の面倒さの原因は、耐久値ではなくマップ間の持ち越しだった
- 装備を外すだけで避けられるデバフは「操作を知っている人だけが得をする」ので入れない（「守りは武器として働く」の判断にも効いた）
- 範囲を作るときは、止まれるマス（`GetReachableCells`）か通れるマス（`GetDistanceMap`）かを使い分ける（補給圏は通れるマスで作った）
- 手作業でアセットを作り直すと GUID が変わるので、参照している全アセットの割り当て直しが要る
  （2026-07-26 の `W_Tome`。敵魔道士の武器が切れて「敵が攻撃してこない」形で現れ、気づきにくかった）
