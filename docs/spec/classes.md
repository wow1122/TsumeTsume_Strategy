# 兵種の仕様

ユニットの職業（兵種）の定義と、分類の用語。移動タイプ・移動力・装備可能武器は兵種で決まる。

- データは `ClassData`（`Assets/_Game/Data/Classes/Class_*.asset`）。移動力の実数値はこのアセットが正で、作者が Unity のエディタで調整する
- 移動タイプの分類は `Units/UnitClass`、特攻タグは `Units/ClassTag`、階級は `Units/ClassTier`
- 飛行兵の決まりは [movement.md](movement.md)、特攻タグの効果は [combat.md](combat.md)

## 兵種の階層と用語

```
徒歩 ─ 歩兵
    └ 重装歩兵
騎乗 ─ 騎兵（輸送隊は騎兵の一種）
    └ 飛行兵
```

- **「歩兵」はゲーム上の呼称どおり通常歩兵だけを指す。2つをまとめて指すときは必ず「徒歩」と呼ぶ**（作者合意）。
  「歩兵」という語に広義と狭義の2つの意味を持たせないため
- コードでは `Class == UnitClass.Infantry` と直接比べず、`IsFoot()`（徒歩）か `IsNormalInfantry()`（通常歩兵のみ）を書く。
  どちらのつもりかがコードに残り、素の比較が残っていないかは grep で見張れる
- 騎兵向けのルールは `IsCavalry()`（騎兵＋輸送隊）、騎乗全体は `IsMounted()`（＝`!IsFoot()`）、飛行兵は `IsFlier()`
- 救出の対象・引き受けの貨物・代わりに降ろす・挟撃のガード役は、すべて徒歩（歩兵＋重装歩兵）が条件。重装歩兵は歩兵と同じ扱い
- 移動タイプは `.asset` に数字で保存される（歩兵0・騎兵1・飛行兵2・輸送隊3・重装歩兵4）ので、途中に挿入すると既存ユニットの兵種が化ける。**追加は必ず末尾**

## 兵種データの合意仕様

- 38種を定義する: 下級14職・上級24職。兵種表は作者提供。聖騎馬兵は槍兵と騎馬兵の**共有**昇格先でアセットは1つ
- 各兵種 = 名前・階級（下級/上級 `ClassTier`）・移動タイプ（`UnitClass`）・移動力・装備可能武器種・特攻タグ・昇格先（下級のみ最大2つ）
- 移動力の例: 剣闘士3・剣士4・重装兵2・騎馬兵6・輸送隊5・飛行兵は6兵種すべて6
- **昇格先はデータのみ**（クラスチェンジの実行はレベル/経験値が前提なので将来実装）
- **特攻タグ**（`ClassTag`。`[Flags]`）: 騎馬1・白翼2・竜4・重装8・竜騎兵16。値は `.asset` に数字で保存されるので、追加は必ず末尾。
  移動タイプとは別軸なので、騎兵である鎧騎馬兵は騎馬＋重装の両方を持つ。輸送隊も騎馬を持つ
- 竜騎兵・大竜騎兵・魔竜騎兵のタグは「竜騎兵」（竜騎兵属性は竜に含まれる）。竜タグを持つ兵種は無い
- 昇格で騎乗になる職（聖騎馬兵・鎧騎馬兵・ノマディ・ヴァルキュリア・ダークナイト）は移動タイプ「騎兵」
  → 騎乗の地形ルール・救出できる（運べる数1）・騎馬タグが付く
- 移動タイプが重装歩兵の兵種＝重装兵・大楯鎧兵（どちらも移動2）。重装タグを持つ兵種＝重装兵・大楯鎧兵・鎧騎馬兵。
  どれも Stage_01 には出ない（検証ステージの敵などで使う）
- 飛行兵の兵種名: 白翼属性＝白翼騎兵・聖白翼騎兵・金鵄兵／竜騎兵属性＝竜騎兵・大竜騎兵・魔竜騎兵（作者指示）。
  上級職の名前は下級職の名前に一字足す形（騎馬兵→聖騎馬兵・竜騎兵→大竜騎兵）にそろえる。
  **「竜騎兵」は属性名と下級職の兵種名が同じ**（作者合意。説明では「竜騎兵属性」「兵種の竜騎兵」と書き分ける）
- 魔法＝魔導＝魔導書は同一の武器種（`WeaponType.Magic`）。光魔法は司祭用の別の武器種（定義のみ）
- 武器制限は**警告のみ**（`UnitData.OnValidate` と `Unit.Initialize` で Console 警告。動作は止めない）
- 武器側にも兵種の限定を持てる（`WeaponData.exclusiveClasses`。判定は `WeaponMemoryRules.CanEquipByClass`＝兵種の装備可能武器と武器側の限定の両方）
- 剣の歩兵（味方兵・ダミー）は剣闘士にする（作者合意）。剣士だと移動4になり、調整済みのバランスが変わるため

**ユニットの能力値の読み方**

- `Unit` は `Initialize` で `UnitData` をコピーした「ランタイム能力値」を使う（`Strength`〜`Move`・`Class`・`Weapon` のプロパティ経由）
- 移動タイプと移動力は `UnitData.EffectiveClass` / `EffectiveMove`（兵種データが優先。未設定なら旧フィールド）
- `Data` を直接読むのは `Unit` の中の窓口だけ。ユニットの列挙は `UnitRegistry`（名簿）経由で、`FindObjectsByType` は使わない
- 数値の調整は作者がエディタで行う（データは ScriptableObject 中心）

## マップ上のユニットの絵

- マップ上のユニットの絵は**兵種単位**で、`ClassData` の `playerMapSprite`（味方用）／`enemyMapSprite`（敵用）に持たせる
  （陣営で絵の色が違うため2枠）。同じ兵種のユニットはダミーや検証用も含めて全員同じ絵になる
- 未設定の枠は**色付きの四角**（味方=青／敵=赤・マスの0.7倍）。行動済みの暗転は絵にも四角にも効く
- 絵は `Assets/_Game/Art/Units/` の `.aseprite`（試運転用・32×32・Aseprite Importer で直接取り込み）
- `Unit.Initialize` が**キャンバス32px＝1マス**の基準で拡縮し（定数 `MapSpriteCanvasPixels`）、作者の調整でその0.9倍にしている。
  Aseprite の取り込みは透明部分を切り詰めるので `sprite.bounds` では測らない。キャンバスが32px以外の絵を足すときはこの定数を見直す
- 絵がある兵種: 剣闘士・剣士・斧使・槍兵・弓使・魔導士・修道士・騎馬兵・白翼騎兵（味方・敵）、輸送隊（味方のみ）。
  竜騎兵・重装兵・鎧騎馬兵などは四角のまま
- **新しい絵を取り込んだら必ず Pivot Alignment を Center にする**（Inspector の Layer Import 内 → Apply）。
  既定の Bottom Center のままだと絵が半マス上にずれる。Filter Mode は既定で Point（変更不要）
