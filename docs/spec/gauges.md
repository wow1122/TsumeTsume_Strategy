# メモリゲージ・覚醒ゲージの仕様

ユニットごとに2本のゲージを持つ。**技＝メモリゲージ→必殺技・武器の支払い／速さ＝覚醒ゲージ→再行動**。

- 目的: 命中・回避・追撃・行動順が無いので、技と速さは三すくみ補正の1か所でしか使われず、個性として働いていなかった。
  この2つに独自の役割を与える
- 数値と可否の判定は `Combat/GaugeRules` に一元化する。調整用の数値はファイル先頭の1ブロックに集約する（敵AIの点数定数と同じ流儀）。
  ScriptableObject 化は必要になってから
- コードの名前: メモリは `Unit.Memory`、覚醒は `Unit.Momentum`（旧名「気勢」の訳語のまま）
- 確認は `Stage_GaugeTest`（[stages-assets.md](stages-assets.md)）
- メモリという名前の由来は [design-notes.md](../design-notes.md)

## メモリゲージ・覚醒ゲージの合意仕様

**数値の扱い（重要）**

- 原案の閾値（技31以上・魔力20/30・覚醒の最大100）は、現行ユニットの能力値（技1〜6・速さ1〜7・魔力0〜6）だと発動しない
  （覚醒は、速さ7が Stage_01 の敵12体を4連続撃破×3回で倒し切ってやっと1本）
- 作者の判断で**原案の数値をそのまま実装し、検証は専用ステージ `Stage_GaugeTest` で行う**（Stage_01 のバランスには手を触れない）。
  Stage_01 で遊べるようにするには、ユニットの能力値を上げるか `GaugeRules` の定数を下げる調整が別途必要

**メモリゲージ（技 → 必殺技・武器の支払い）**

- ゲージ値は 0〜30、貯まったゲージ（ストック）は **2本まで**保持できる
- **初期値＝技の値**をマップ開始時にそのまま入れる（`Unit.Initialize`）。30 に達した分は
  1本に変換され超過分が残る（技31 → 1本＋1／技30 → 1本＋0）
- **上昇は自陣営のフェイズ開始時**。魔力30以上→+3、20以上→+2、それ未満→+1。格納中の貨物にも入る。
  **ターン1は初期値のまま**（`BattleSetup` と `TurnManager` のどちらの Start が先に走るかを Unity が保証しないため、
  「ターン2以降に増える」と明示的に決めている）
- 30 に達したらストック+1、超過分は次のゲージへ繰り越す。**ストックが2本のときは30で頭打ち**（あふれた分は捨てる）
- 武器の攻撃の支払いにも使う（[weapons.md](weapons.md)）

**必殺技**

- 行動メニューの「攻撃」の直後に出る。条件は、メモリが1本以上あって、「1本（30）＋その武器の消費」を払える武器で届く敵がいること
- 対象選択の流れは攻撃と同じで、**その一撃の最終ダメージが2.0倍**になる（`GaugeRules.CriticalMultiplier`）。**行動を消費する**
- **メモリが減るのは対象を確定した瞬間**なので、対象選択で右クリックして戻ってもメモリは失われない
- **倍率がかかるのは本人の一撃だけ。挟撃の追撃は等倍**。杖ユニットには出ない（攻撃対象がいないため）

**覚醒ゲージ（速さ → 再行動）**

- ゲージ値は 0〜100、ストックは **2本まで**。初期値は全員 0
- **撃破するたびに貯まる**。戦闘1回（`CombatSystem.ResolveAttack` 1回。挟撃のとどめも含む）で
  相手を倒したら連鎖+1、倒せなかったら連鎖リセット。フェイズの切り替わりでもリセット
- **1回の量は連続撃破の数で3段階**（作者仕様）: **1体目＝速さの半分（切り捨て）・2連続目＝速さ・
  3連続目以降＝速さの2倍**。連鎖が切れたら、次の撃破は速さの半分に戻る。割合は `GaugeRules` の
  `MomentumPercentFirst`／`Chain2`／`Chain3Plus`（50・100・200％）。例: 速さ7なら 3 → 7 → 14 → 14…
- 配る相手は**倒した側の陣営の全生存ユニット**で、量は**各自の速さ**で計算する（作者確認）。
  **格納中の貨物にも入る**ので `UnitRegistry.All` を使う（`GetUnits` は盤上のユニットしか返さない）

**再行動**

- 何も選んでいないときに**行動済みの味方をクリック**すると「再行動」1項目のメニューが出る（覚醒が1本以上のとき）。
  攻撃の結果を見てから使うか決められるように、行動を終えた後の入口にしてある（行動前に宣言する方式は作者が不採用）
- 実行すると覚醒1本を消費して行動済みを解除し、通常の移動選択に戻る。`ActionContext` が
  作り直されるので移動力は全回復し、救出済みなどの制限も引きずらない＝まっさらな1行動
- **回数の制限なし**（作者指示）: 覚醒が残っていれば、同じユニットが同じターンに何回でも再行動できる。
  制限が必要になったら作者から相談する
- **味方全員が行動済みでも、再行動できる味方がいる間はターンが自動終了しない**（`TurnManager.NotifyUnitActed`）。
  最後の1体が行動した瞬間に終わると使う隙が無くなるため。終えるときはコマンド一覧の「終了」を選ぶ

**共通**

- **敵もゲージは貯まる**（蓄積のコードは陣営を区別しない）が、**敵AIは当面使わない**（表示は敵味方どちらにも出す）
- ゲージの増減APIは**「純粋な状態変更」に保つ**（`Unit.Equip` / `Unequip` と同じ理由。ログ・演出・行動消費は呼び出し側に置く）
- 表示: ユニット情報パネルの右カラム最下部に、メモリ（明るい緑）→ 覚醒（明るい黄色）の順で2本のバー（`UI/GaugeBars`）。
  値10ごとに黒い縦線、右に「n本 値／最大」。盤上にはリング状のゲージも出す（[ui-board.md](ui-board.md)）
