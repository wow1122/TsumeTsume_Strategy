# メモリゲージ・覚醒ゲージの仕様

### メモリゲージ・覚醒ゲージの合意仕様（フェーズ28〜30・2026-07-26 作者合意。2026-10-24 にマナゲージから、2026-10-25 に気勢ゲージから改名）

**2026-10-24 の改名**: マナゲージを**メモリゲージ**へ改名した（作者仕様。画面の文字もコードの名前も＝`Unit.Memory`・
`GaugeRules.MaxMemory` など。検証ユニットのファイル名 `Unit_Test_Mana31` などは GUID 保全のため旧名のまま）。
貯まり方（技＝初期値・魔力で上昇・30で1本・2本まで）は変わらない。メモリは必殺技に加えて
**武器の攻撃の支払い**にも使うようになった（「メモリゲージで払う武器の合意仕様」の節）

**2026-10-25 の改名**: 気勢ゲージを**覚醒ゲージ**へ改名した（作者の決定。画面の文字・ログ・コメントの「気勢」を
すべて「覚醒」に。コードの名前は `Unit.Momentum` などのまま）。貯まり方・使い方は変わらない
（貯まり方はこのあと同日に作者の仕様で変えた＝下の「覚醒ゲージ」の箇条）

- **目的**: 技と速さは三すくみ補正（CombatRules.GetTriangleModifier）の1か所でしか使われておらず、
  命中・回避・追撃・行動順が無いためキャラクターの個性としてほとんど働いていなかった。
  **技＝メモリゲージ（旧マナ）→必殺技／速さ＝覚醒ゲージ（旧気勢）→再行動**という独自の役割をこの2つに与える
- **数値の扱い（重要）**: 原案の閾値（技31以上・魔力20/30・覚醒の最大100）は、
  現行ユニットの能力値（技1〜6・速さ1〜7・魔力0〜6）だと一度も発動しない
  （覚醒は 2026-10-25 の変更後、速さ7が Stage_01 の敵12体を4連続撃破×3回で倒し切ってやっと1本＝実質届かない）。
  作者の判断で**原案の数値をそのまま実装し、検証は専用ステージ Stage_GaugeTest で行う**
  （Stage_01 のバランスには手を触れない）。Stage_01 で遊べるようにするには、
  ユニットの能力値を上げるか GaugeRules の定数を下げる調整が別途必要
- **調整用の数値は Combat/GaugeRules.cs 先頭の1ブロックに集約**（敵AIの点数定数と同じ流儀）。
  ScriptableObject 化は必要になってから

**メモリゲージ（技 → 必殺技・武器の支払い）**

- ゲージ値は 0〜30、貯まったゲージ（ストック）は **2本まで**保持できる
- **初期値＝技の値**をマップ開始時にそのまま入れる（Unit.Initialize）。30 に達した分は
  1本に変換され超過分が残る（技31 → 1本＋1／技30 → 1本＋0）
- **上昇は自陣営のフェイズ開始時**（行動済みのリセットと同じ場所）。魔力30以上→+3、20以上→+2、それ未満→+1。
  **ターン1は初期値のまま**（BattleSetup と TurnManager のどちらの Start が先に走るかを
  Unity が保証しないため、「ターン2以降に増える」と明示的に決めている）
- 30 に達したらストック+1、超過分は次のゲージへ繰り越す。**ストックが2本のときは30で頭打ち**（あふれた分は捨てる）
- **必殺技**＝行動メニューの「攻撃」の直後に出る（攻撃できる相手がいて、かつメモリが1本以上のとき）。
  対象選択の流れは攻撃と同じで、**その一撃の最終ダメージが2.0倍**になる（GaugeRules.CriticalMultiplier）。
  **行動を消費する**（攻撃と同じ）。**メモリが減るのは対象を確定した瞬間**なので、対象選択で
  右クリックして戻ってもメモリは失われない。
  2026-10-24 から**武器のメモリ消費も一緒に払う**＝「1本（30）＋その武器の消費」を両方払える武器だけが
  武器の一覧で選べる（GaugeRules.CriticalMemoryCost を extraCost として渡す）
- **倍率がかかるのは本人の一撃だけ。挟撃の追撃は等倍**。杖ユニットには出ない（攻撃対象がいないため）

**覚醒ゲージ（速さ → 再行動）**

- ゲージ値は 0〜100、ストックは **2本まで**。初期値は全員 0
- **撃破するたびに貯まる**。戦闘1回（CombatSystem.ResolveAttack 1回。挟撃のとどめも含む）で
  相手を倒したら連鎖+1、倒せなかったら連鎖リセット。フェイズの切り替わりでもリセット
- **1回の量は連続撃破の数で3段階**（2026-10-25 作者仕様）: **1体目＝速さの半分（切り捨て）・2連続目＝速さ・
  3連続目以降＝速さの2倍**。連鎖が切れたら、次の撃破は速さの半分に戻る。割合は GaugeRules の
  MomentumPercentFirst／Chain2／Chain3Plus（50・100・200％）。例: 速さ7なら 3 → 7 → 14 → 14…
  ※旧版（2026-07-26）は「2連続目以降、撃破1回につき 速さ÷2」（1体目では貯まらない＝連続で撃破した数 − 1 回分）。
  その初版は「2連続目に2回分さかのぼる」だったが、Play 確認後に作者が変えていた
- 配る相手は**倒した側の陣営の全生存ユニット**で、量は**各自の速さ**で計算する（**格納中の貨物にも入る**ので
  UnitRegistry.All を使う。GetUnits は盤上のユニットしか返さない）。2026-10-25 の変更でも配る相手は同じ（作者確認）
- **再行動**＝Idle で**行動済みの味方をクリック**すると「再行動」1項目のメニューが出る
  （覚醒が1本以上のとき）。攻撃の結果を見てから使うか決められるように、
  行動を終えた後の入口にしてある（行動前に宣言する方式は作者が不採用）
- 実行すると覚醒1本を消費して行動済みを解除し、通常の移動選択に戻る。**ActionContext が
  作り直されるので移動力は全回復**し、救出済みなどの制限も引きずらない＝まっさらな1行動
- **回数の制限なし**: 覚醒が残っていれば、同じユニットが同じターンに何回でも再行動できる
  （2026-10-25 作者指示。制限が必要になったら作者から相談する）。
  ※旧版は「1ユニットにつき1ターン1回まで」（Unit.UsedRefreshThisTurn。自陣営フェイズ開始でリセット）。
  この印は 2026-10-25 にコードから消した
- **味方全員が行動済みでも、再行動できる味方がいる間はターンが自動終了しない**
  （TurnManager.NotifyUnitActed）。最後の1体が行動した瞬間に終わると使う隙が無くなるため。
  終えるときは「ターン終了」ボタンを押す。再行動した後もまだ覚醒が残っていれば、同じく自動では終わらない

**共通**

- **敵もゲージは貯まる**（蓄積のコードは陣営を区別しない）が、**敵AIは当面使わない**
  （「敵は救出系／所持品／交換を使わない」と同じ前例。EnemyAI は無変更）。表示は敵味方どちらにも出す
- ゲージの増減APIは**「純粋な状態変更」に保つ**（Unit.cs の Equip / Unequip の警告コメントと同じ理由。
  ログ・演出・行動消費は呼び出し側に置く）
- UI: メモリ（明るい緑）→ 覚醒（明るい黄色※2026-10-10 に明るい青から変更）の順で2本のバー。
  値10ごとに黒い縦線、右に「n本 値／最大」。
  部品は UI/GaugeBars。2026-08-16 の刷新後は**ユニット情報パネルの右カラム最下部**に出る
  （同じ部品に、仕様未定の兵種経験値バー用の `DrawSlim`＝半分の太さ・同じ長さ が足してある）
- 盤上にもリング状のゲージを出す（2026-10-10。「盤上の表示と画面サイズの合意仕様」の節）
