# 敵AIの仕様

- 本体は `AI/EnemyAI`、盤面の危険の読み取りは `AI/ThreatMap`、性格は `AI/EnemyAIProfile`、行動予定は `AI/ActionPlan`
- 射程・挟撃・ダメージの判定はプレイヤーと同じ `CombatRules` / `CombatSystem` を使う
- **敵が使わないもの**: 救出系・持ち物と道具・交換・必殺技と再行動・剣の撃破後1マス再移動。
  装備が替わるのは、メモリで払えなくなったときの自動の持ち替えだけ（[weapons.md](weapons.md)）
- 確認は検証ステージ `Stage_AITest_*` で行う（[stages-assets.md](stages-assets.md)）

## 思考の流れ

- **考える → 動かす の2段構え**: `Evaluate` が盤面を変えずに行動を選んで `ActionPlan` を返し、`Execute` がそれを実行する
- **考える順番**: 攻撃 → 待ち伏せゲート → ガード → 接近。上の段で行動が決まれば下の段へは進まない
- **攻撃の点数**（`ScoreAttack`）＝ 予測ダメージ（`PredictTotalDamage`。挟撃・ガード込み）＋ ボーナス。
  ボーナスの大小がそのまま優先順位になる: **撃破 1000 ＞ 集中攻撃 200 ＞ ガード役潰し 50 ＞ 挟撃のお膳立て 2**。
  定数は `EnemyAI` の先頭の1ブロックに集約する
- **同点の決め方**: 地形防御の高いマス → 移動の少ないマス（飛行兵は地形防御0として扱う）
- 後衛武器の敵は、静止したままなら武器上限まで撃ち、隣接されたら離れたマスへ移動して撃つ動きが自然に出る
  （動くと射程が2マスちょうどに縮むため）
- **接近は距離マップの3段構え**（`PlanApproach`）。目標は「どこかのプレイヤーを攻撃できる立ち位置」全部で、
  移動してから撃つ前提で見積もる（後衛武器は最小射程の輪）
  1. 経路: プレイヤーのマスは通れない前提の、本当の道のり（`MovementCalculator.GetDistanceMap`）
  2. 敵を無視した経路: 道がプレイヤーに塞がれて全滅したとき。門に栓をされても門前へ整列し、射程に入れば塞いだ相手を攻撃する
  3. 直線距離: それでも道が無いとき。凍結しないための保険
- **行動順は名簿順＝ステージの配置順**。機能どうしの噛み合わせを決める要素なので、配置を変えるときは意識する
- 敵は `EnemyPhaseRoutine` の中で「開始時に全員未行動 → 動いた敵から行動済み（暗くなる）→ 終了時に戻す」と管理する。
  挟撃のお膳立てや集中攻撃が「まだ動いていない味方」を見られるようにするため
- **思考ログ**: 敵1体につき1行、何を考えたかを日本語で Console に出す（`TurnManager.enemyAILog` を Inspector で切り替え）
- static な状態は `RuntimeInitializeOnLoadMethod` でリセットする（エディタで再生を繰り返しても前回の値が残らないように）

## 敵AIの性格付けの合意仕様

- 性格は配置ごとに指定する（`StageData.Placement.aiProfile`。敵のみ有効・未記載＝突撃型）。種類は突撃型と待ち伏せ型の2つ
- 待ち伏せ型は**挑発されるまで一切動かない**（接近もしない）。ただし攻撃探索は通すので、
  射程圏（移動＋射程）に入られたら普通に移動して攻撃する。立ち位置による受動的な効果（隣の味方への挟撃ガード）は未挑発でも効く
- 挑発の条件は2つ: 「被弾している（CurrentHP < MaxHP）」または「今すぐ攻撃できる相手がいる（攻撃すること自体が挑発）」。
  連鎖挑発（近くの味方の起動で自分も起動）は無し
- **挑発は永続**（`Unit.IsProvoked`）。挑発後はずっと突撃型として振る舞う＝一度起動した敵は、プレイヤーが退いても持ち場に戻らず追ってくる
- Stage_01 は城内4体（門の弓兵2・魔道士・敵白翼騎兵 (10,9)）が待ち伏せ型。敵白翼騎兵 (3,9) と野戦部隊7体は突撃型

## 挟撃の活用の合意仕様

挟撃を「完成させる」側は `PredictTotalDamage` が挟撃込みで評価するので、元から最適に動く。足しているのは次の2つの加点。

- **お膳立て**（`PincerSetupBonus` +2）: 隣接攻撃のマス選びで、反対側マスに「未行動・前衛武器・自分以外」の味方が移動で立てるなら加点する。
  控えめな値なので実ダメージ差1点までしか覆さない。後続の味方がもっと良い獲物を選ぶかもしれない投機的な手なので、実利を犠牲にしない（作者合意）
- お膳立ての条件: 隣接攻撃／相手がガードされていない（`IsPincerNegated` が false）／反対側マスが盤内かつ空き／後続の味方がそこへ到達できる。
  後続の到達マスは `TakeAction` ごとに1回だけ計算する（`BuildPincerHelpers`）。
  待ち伏せ型の未挑発の味方も後続に含む（挟みに行く攻撃自体が挑発になるため）
- **ガード役潰し**（`GuardBreakKillBonus` +50）: 一撃で倒せる相手が複数いるとき、誰かの挟撃ガード役をしている相手（`IsGuardingSomeone`）を優先して倒す。
  撃破ボーナスが付くときだけ加える（ガードはHPが残る限り有効なので、倒し切れなければ無意味）
- 思考ログに「・挟撃のお膳立て」「・ガード役潰し」と書く
- `CombatRules.GetPincerOppositeCell`（反対側マス）と `WouldGuardAt`（仮定の位置でのガード判定）が部品。
  `FindPincerAlly` / `FindPincerGuard` もこの上に作ってある

## ガードの活用の合意仕様

- **攻撃優先**: ガード役の敵でも、攻撃できる相手がいれば必ず攻撃する（守り位置を離れて攻撃に行くこともある。思考ログで分かる）
- **ガード＞接近**: 防げるダメージが1以上なら接近よりガードを優先する（作者合意）。
  マスの選び方は 防止量の合計 → 地形防御 → 移動の少なさ の順。
  1マスで複数の味方を守れたら防止量は合算する。候補に現在地も含むので「その場で守り続ける」が出る
- ガード役になれるのは前衛武器の徒歩ユニットのみ（`WouldGuardAt` と同じ条件）。未挑発の待ち伏せ型はガード移動しない
- 脅威の判定は `ThreatMap.FindPincerThreatenedAllies(grid, self)`: self 以外に未ガードの味方ごとに上下／左右の対マスを調べ、
  両側それぞれに「前衛のプレイヤーが既に立っている、または空きマスで移動して立てる」があり、両側が別々のプレイヤーなら脅威。
  防止量＝挟撃に参加できるプレイヤーの最大ダメージ（やや過大な見積り）
- self（これから動く敵）は盤面に居ない扱いで判定する: 自分のガードは「ガード済み」に数えず、自分が塞いでいる対マスは空き扱い。
  これが無いと、守り続けている敵が翌ターン「もう守られている」と勘違いして持ち場を離れる
- 先に動いた敵が守った味方は `IsPincerNegated` になり、自動で脅威から外れる（重複ガードの防止）
- ガード役自身が挟撃される可能性は読まない（許容・ログで分かる。作者合意）

## 集中攻撃の合意仕様

- 敵フェイズの開始に1回だけ、`EnemyAI.BeginEnemyPhase` が「皆で掛かれば倒し切れる相手」を**1体だけ**集中攻撃の目標（`focusTarget`）に選ぶ
- 火力見込みの数え方: プレイヤー1人ごとに、参加できる敵の「後衛武器の単発ダメージの合計 ＋ 近接ダメージの上位k件」
  （k＝そのプレイヤーの隣接マスのうち、盤内で「空き or 敵占有」の数＝近接が取り付ける口の数）。
  参加できる敵＝未行動 かつ（突撃型 or 挑発済み）
- 目標の条件: 火力見込み ≥ 現在HP。候補が複数なら最小HP優先（同点は名簿順）。いなければ「目標なし」で各自判断。
  挟撃の追加打や本当に到達できるかまでは見ない大づかみの見積りで、外れても攻撃が集中して削れるだけなので許容する（作者合意）
- `FocusBonus` +200: 目標への攻撃に加点する。撃破ボーナスより下（目の前の確実な撃破は捨てない）・ガード役潰しより上（倒せる相手がいないときは皆で同じ相手を削る）
- 目標が倒れたら、次の敵の思考開始時に**再選定**する（`focusAssigned` で管理。倒れたユニットは Destroy で参照が null になるため、「元から目標なし」との区別に必要）
- 思考ログ: フェイズ開始に「AI方針: 集中攻撃の目標 = …（HP・火力見込み）」、各行動の理由に「・集中攻撃」
