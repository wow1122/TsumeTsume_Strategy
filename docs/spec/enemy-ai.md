# 敵AIの仕様

- 敵AI: 攻撃先・接近先の点数が同点なら地形防御の高いマスを優先（飛行兵は地形防御0扱い）。
  既知の限界: 接近はマンハッタン距離基準のため、城壁の向こうの敵が門へ回り込まないことがある
  （次期の敵AI強化で対応予定）
### 敵AIの性格付けの合意仕様（Phase 17・2026-07-17 作者合意）

- 性格は配置ごとに指定（StageData.Placement.aiProfile。敵のみ有効・未記載=突撃型）。
  種類は突撃型（従来どおり）と待ち伏せ型の2つ
- 待ち伏せ型は**挑発されるまで一切動かない**（接近もしない）。ただし攻撃探索は通すので、
  射程圏（移動+射程）に入られたら普通に移動して攻撃する。
  立ち位置による受動的な効果（隣の味方への挟撃ガード）は未挑発でも効く
- 挑発の条件は2つ: 「被弾している（CurrentHP < MaxHP）」または
  「今すぐ攻撃できる相手がいる（攻撃すること自体が挑発）」。
  連鎖挑発（近くの味方の起動で自分も起動）は v1 では無し
- **挑発は永続**（Unit.IsProvoked。戻す手段なし）。挑発後はずっと突撃型として振る舞う
  → 一度起動した敵は、プレイヤーが退いても持ち場に戻らず追ってくる
- Stage_01 は城内4体（門の弓兵2・魔道士・敵白翼騎兵(10,9)）が待ち伏せ型。
  敵白翼騎兵(3,9)と野戦部隊7体は突撃型のまま
- 「挑発後も動かない完全固定砲台型」が欲しくなったら3つ目の性格として追加可能（先送り）
- 検証用ステージ: Stage_AITest_Ambush（10×10・砦(7,7)に待ち伏せ敵兵・(2,8)に待ち伏せ敵弓兵）

### 挟撃の活用の合意仕様（Phase 18・2026-07-17 作者合意）

- 挟撃を「完成させる」側は従来から最適（PredictTotalDamage が挟撃込みで評価）。
  本フェーズで足したのは「お膳立て」側と「ガード役潰し」の2つの加点
- お膳立て（PincerSetupBonus +2）: 隣接攻撃のマス選びで、反対側マスに
  「未行動・前衛武器・自分以外」の味方が移動で立てるなら加点。
  控えめな +2 なので実ダメージ差1点までしか覆さない（お膳立ては投機的 —
  後続の味方がもっと良い獲物を選ぶかもしれない — ので実利を犠牲にしない。作者合意）
- お膳立ての条件: 隣接攻撃／相手が非ガード状態（IsPincerNegated が false）／
  反対側マスが盤内かつ空き／後続の味方がそこへ到達可能。
  後続の到達マス集合は TakeAction ごとに1回だけ計算（BuildPincerHelpers）。
  待ち伏せ型の未挑発の味方も後続候補に含む（挟みに行く攻撃自体が挑発になるため）
- ガード役潰し（GuardBreakKillBonus +50）: 一撃で倒せる相手が複数いるとき、
  誰かの挟撃ガード役をしている相手（IsGuardingSomeone）を優先して倒す。
  撃破ボーナスが付くときだけ加算（ガードはHPが残る限り有効なので、倒し切れなければ無意味）
- 点数の階層: KillBonus 1000 ＞（Phase 21 予定: 集中攻撃 200）＞ ガード役潰し 50 ＞ お膳立て 2
- 思考ログに「・挟撃のお膳立て」「・ガード役潰し」を表記
- 抽出リファクタ（挙動不変）: CombatRules.GetPincerOppositeCell（反対側マス）と
  WouldGuardAt（仮定位置でのガード判定。Phase 19 の守り配置AIで使う）を新設し、
  FindPincerAlly / FindPincerGuard をその上に再実装
- 検証用ステージ: Stage_AITest_Pincer（10×10・森(3,4)のみ。ダミー(3,3)を敵兵(3,6)が
  平地(2,3)からお膳立て→敵兵(6,5)が(4,3)で挟撃完成。味方兵(1,1)を隣接させるとガードで
  お膳立てが消えて森に戻る。北東のダミー3体+敵兵(8,5)はガード役潰しの確認用 —
  ダミーのHPを一時的に5へ下げると「撃破・ガード役潰し」が観察できる）

### ガードの活用の合意仕様（Phase 19・2026-07-18 作者合意）

- 攻撃優先: ガード役の敵でも攻撃できる相手がいれば必ず攻撃する
  （守り位置を離れて攻撃に行くこともある。思考ログで分かる）
- ガード＞接近: 防げるダメージが1以上なら接近よりガードを優先。
  マスの選び方は 防止量の合計 → 地形防御 → 移動の少なさ の順
  （1マスで複数の味方を守れたら防止量は合算。候補に現在地も含むので「その場で守り続ける」が出る）
- ガード役になれるのは「前衛武器の徒歩ユニット（歩兵・重装歩兵）」のみ（WouldGuardAt と同条件）。
  未挑発の待ち伏せ型はガード移動しない（性格ゲートが先。立ち位置による受動ガードは効く）
- 脅威の判定は AI/ThreatMap.FindPincerThreatenedAllies(grid, self):
  （self 以外に）未ガードの味方ごとに上下/左右の対マスを調べ、両側それぞれに
  「前衛のプレイヤーが既に立っている or 空きマスで移動して立てる」があり、両側が
  別々のプレイヤーなら脅威。防止量 = 挟撃に参加できるプレイヤーの最大ダメージ（やや過大見積り）
- self（これから動く敵）は盤面に居ない扱いで判定する（ロードマップの案から引数を1つ追加）:
  自分のガードは「ガード済み」に数えない＋自分が塞いでいる対マスは空き扱い
  （相手の到達判定は「隣まで来られれば入れる」の安全側の丸め）。
  これが無いと、守り続けている敵が翌ターン「もう守られている」と勘違いして持ち場を離れる
- 先に動いた敵が守った味方は IsPincerNegated になり自動で脅威から外れる（重複ガード防止）
- ガード役自身が挟撃される可能性は v1 では読まない（許容・ログで分かる。作者合意）
- 検証用ステージ: Stage_AITest_Guard（10×10全平地・味方騎兵(4,0)(6,0)・敵兵(2,6)(2,4)・
  待ち伏せ型の敵魔道士(5,6)。敵兵が(4,6)へ守りに動き「ガード・最大12ダメージ防止」、
  2体目は接近（重複ガードしない）、騎兵を退げると脅威が消えて守りをやめる）

### 集中攻撃の合意仕様（Phase 21・2026-07-18 作者合意）

- 敵フェイズの開始に1回だけ、EnemyAI.BeginEnemyPhase が「皆で掛かれば倒し切れる相手」を
  **1体だけ**集中攻撃の目標（focusTarget）に選ぶ（TurnManager が敵の行動ループの前に呼ぶ）
- 火力見込みの数え方: プレイヤー1人ごとに、参加できる敵の
  「後衛武器の単発ダメージの合計 ＋ 近接ダメージの上位k件」
  （k = そのプレイヤーの隣接マスのうち盤内かつ「空き or 敵占有」の数＝近接が取り付ける口の数）。
  参加できる敵 = 未行動 かつ（突撃型 or 挑発済み）の敵のみ
- 目標の条件: 火力見込み ≥ 現在HP（今フェイズ中に倒し切れる見込みがある相手だけ狙う）。
  候補が複数なら最小HP優先（同点は名簿順）。いなければ「目標なし」で従来どおりの各自判断
- FocusBonus +200: 目標への攻撃に加点。撃破ボーナス 1000 より下（目の前の確実な撃破は
  捨てない）・ガード役潰し 50 より上（倒せる相手がいないときは皆で同じ相手を削る）
- 目標が倒れたら、次の敵の思考開始時に**再選定**する（focusAssigned フラグで管理 —
  倒れたユニットは Destroy で参照が null になるため「元から目標なし」との区別に必要）
- static な状態（focusTarget など）は RuntimeInitializeOnLoadMethod でリセット
  （UnitRegistry と同じパターン。エディタで再生を繰り返しても前回の目標が残らない）
- 思考ログ: フェイズ開始に「AI方針: 集中攻撃の目標 = …（HP・火力見込み）」、
  各行動の理由に「・集中攻撃」を表記
- 検証用ステージ: Stage_AITest_Focus（10×10 全平地・弱ダミーHP12 が (4,4)(8,6)・
  通常ダミー(2,4)・敵斧兵4体。ターン1で「弱ダミーへ収束→撃破→もう1体へ再選定」、
  ターン2で「目標なし」のログが見える）
