# 武器の仕様

### メモリゲージで払う武器の合意仕様（2026-10-24 作者仕様・ブランチ memory-weapons）

作者の仕様書 `Desktop/# メモリゲージ使用による武器仕様改善案.md` に基づく。武器の耐久（フェーズ31）と
輸送隊の補給（フェーズ32）を撤廃し、その代わりに**強い武器ほど攻撃のたびにメモリゲージ（旧マナ）を払う**形にした。
作者の「案ごとにブランチを切って試し、採用する仕様を選ぶ」方針の1本目で、**同日に作者が採用して main へマージした**。
計画書: `/home/wawo/.claude/plans/harmonic-pondering-penguin.md`（WSL側）

**ルール**

- 武器で1回攻撃するたびに、その武器のメモリ消費（`WeaponData.memoryCost`）を払う。鉄の武器・杖は0
- **払い方は本数も崩して合計から**（作者合意）: 合計＝本数×30＋値。1本＋3＝33 から5を払うと 0本＋28
- **装備はメモリに関係なくできる**（兵種が扱える武器なら）。**払えない武器では攻撃できない**
  ＝攻撃の武器一覧で「（メモリ不足）」の灰色行。持ち物の行にも同じ目印が付き、
  ユニット情報の持ち物の行の右端「消費N」が赤字になる
- 攻撃を受けたときは**装備している武器どおりに働く**（作者合意）＝三すくみ・挟撃のガード役・
  飛行兵の足止め（すり抜け阻止）にメモリは要らない。メモリが要るのは**攻撃と挟撃の支援だけ**
- **挟撃の支援役も自分の武器の消費を払う**。払えなければ挟撃は起きない（仕様書どおり）
- 払うのは戦闘の判定がすべて終わってから、攻撃側 → 挟撃の支援役の順（フェーズ31の耐久の消耗と同じ位置）
- **味方は自動で持ち替えない**: 払った後にその武器を払えなくなっても装備したまま。次の攻撃で
  武器の一覧から払える武器を選ぶ（選ぶと装備も替わる＝「攻撃時の武器選択の合意仕様」の仕組みのまま）。
  マップ開始時も初期装備のまま始める（初期装備の消費が技を上回ると Inspector で警告）
- **敵だけは自動で持ち替える**（作者合意。敵は武器を選ぶ操作を持たないため）: 払えなくなったら、
  持ち物のうち兵種が装備できて払える武器の中で**消費の低い順・同じなら持ち物の上の方**へ（無ければ非武装）。
  マップ開始時にも同じ判定をする。いまの敵は全員が消費0の武器しか持たないので、どのステージでもまだ起きない
  （持ち替え先の選び方は、段階2で味方の持ち替えとして Play 確認済み）
- **必殺技は「1本（30）＋その武器の消費」**: 両方払える武器だけが一覧で選べる（既定）
- 消費・支援の条件は敵味方対称。メモリは敵にも貯まる（従来どおり）

**経緯（同日に1回見直し）**: 最初は仕様書どおり「払えない武器は装備できない・払えなくなったら一番安い武器へ
自動で持ち替える」で実装し、作者が Play で確認した（段階2）。その後、作者が「装備できない形で一貫性を保つより、
プレイヤー自身に選ばせて、いま何を装備しているかを自分の操作の結果にした方がルールを理解しやすい」と見直し、
味方の装備の制限と自動の持ち替えをやめた（段階3b）。そのとき決めた2点（ダイアログ）:
守り＝武器として働く（非武装扱いにすると、攻撃の後に持ち替える操作を忘れた人だけが損をする＝2026-08-03 に
傷んだ武器のデバフを廃止したのと同じ理由）／敵＝今どおり自動で持ち替える

**武器の装備付与（仕様書の「装備付与」と武器種の特性）**

- 鋼の武器・中級魔導: 装備中は**速さが移動力ぶん下がる**（0未満にならない。飛行兵は移動6なので −6）。
  `Unit.Speed` 窓口で効くので、三すくみの補正と覚醒の貯まり方の両方に効く。ユニット情報の速さは「2(-3)」
- 魔法武器（ソニックソード・フレイムランス・ボルトアクス・シャイニングボウ）: **魔力 vs 魔防**で計算。
  三すくみ・有効・特効は武器種のまま。仕様書の「射程1〜2（要相談）」は作者の回答で**射程1**
  （前衛の3本）。シャイニングボウは弓なので弓の射程（静止2〜3・移動後2）
- 三すくみ逆転（アーマーキラー＝重装・斬馬刀＝騎馬・風薙ぎの剣＝白翼）: 相手がそのタグを持ち、かつ
  剣に勝つ武器（槍）を装備しているとき、**有利と不利が入れ替わる**。攻めるとき・攻められるとき・
  挟撃の追撃のすべて。戦闘予測に「※三すくみ逆転（斬馬刀）」
- 長弓: 最大射程だけ+1（静止2〜4・移動後2）。**弓聖（Class_Sniper）専用**（仕様書の「スナイパー」）。
  武器ごとの兵種の限定（`WeaponData.exclusiveClasses`）。ほかの兵種では「装備不可」
- **剣は敵を倒すと1マス再移動できる**（仕様書「剣：敵撃破後１マスのみ再移動可能」）: 剣で攻撃した戦闘で
  相手が倒れたら（挟撃のとどめ・必殺技も含む）、上下左右の1マスへ動ける。地形のコストは問わない
  （入れない地形・誰かがいるマスは不可）。動かずに終えてもよい（自分のマス・右クリック・ESC）。
  勝利が決まった・動けるマスが無いときは出ない。**敵AIは使わない**（救出系などと同じ前例）
- 槍＝騎馬白翼有効・斧＝重装竜騎兵有効・弓＝白翼特効・魔導書＝竜特効（竜騎兵も含む） は従来の EffectiveRules の表どおり

**いまの数値での算数（Stage_01・レビュー時に作者へ提示済み）**

- メモリは「技」で始まり毎ターン+1（全員の魔力が20未満）。技5の味方兵が20ターンで払える量は 5+19＝24
  ＝キラー系なら6回・銀なら2回。味方の技は3〜6なので鋼・銀は開始時ほぼ使えない＝**戦いのほとんどは鉄の武器**
- 鉄の武器で威力が上がった: 剣槍斧 5→6（+1点）・弓魔導書 5→8（+3点、特効なら+9点）。
  敵弓兵→味方飛行兵（HP20）は 18→27 で、移動して撃っても一撃
- 斬馬刀→敵槍騎兵（HP20）は 16→26 で一撃（三すくみ逆転で不利−2 が有利+2 に）
- 鋼の「速さ−移動力」は、いまの技・速さ（1桁）では三すくみの補正が最低値2に張り付く場面が多く、効き目は小さい
  （速さが効くのは、攻撃を受けるときの三すくみの補正と、覚醒の貯まり方）

**実装の要点**

- 判定の窓口は `Combat/WeaponMemoryRules`（CanAfford・CanEquipByClass・PayForAttack・AutoSwitchIfUnaffordable・FindAutoEquip）
- **「払えない武器では攻撃できない」は `CombatRules.TryGetAttackRange` の1か所**（射程なしを返す）。呼び出し4か所
  （CanAttack・GetAttackFromCells・赤い攻撃範囲・武器一覧の理由。5か所目の敵AIの対空圏は撤廃）はすべて攻撃の判定なのでそろう。
  `Unit.Weapon` は払えない武器もそのまま返す（守りで武器として働かせるため）
  ※段階2では Weapon 窓口が null を返す手口（フェーズ31の耐久と同じ）だったが、守りまで非武装扱いになるので段階3bでやめた
- 挟撃の支援役のメモリは `CombatRules.FindPincerAlly` が見る。ガード役（`WouldGuardAt`）は見ない
- 自動の持ち替えは `WeaponChoiceRules.CanChooseWeapon` が false の陣営（＝敵）だけ＝「武器を選べる陣営は自動で持ち替えない」
- 払い・持ち替えはログを伴う本番の処理なので、戦闘予測や敵AIの見積りからは呼ばない（副作用の無い CanAfford・CostOf・MemoryOf を使う）
- 剣の再移動の判定（と撤廃前の撃墜の判定）は、使った武器を**戦闘の前に控えて**決める（敵は払った後に持ち替わるため）
- 戦闘予測: 「武器: 鋼の剣（消費5）」「メモリ 14 → 9」（必殺技は1本も込み）「※攻撃後、この武器はメモリ不足で使えなくなる」
  「挟撃 +12（試験・支援・メモリ5）」「※三すくみ逆転（斬馬刀）」「※剣で倒すと、攻撃の後に1マス再移動できる」
- 敵AIの点数定数は変えていない（敵は平時いつも払える武器を持つので、Weapon 窓口・CanAttack 経由で自動追随）。
  ThreatMap の挟撃の脅威は払えるかを見ない＝従来どおりのやや過大見積り

### 攻撃時の武器選択の合意仕様（2026-08-09 作者要望）

- 攻撃は**武器を選んでから相手を選ぶ**（FE の古典的な流れ。作者が操作順を3度見直した末の最終形）:

  ```
  行動メニュー「攻撃」／「必殺技」
    → 【武器選択】ユニットの右隣に武器の一覧（武器1本でも必ず出る）
         ・行にホバー → その武器で狙える敵が盤面で赤く光る
         ・使えない武器は理由付きの灰色行（「（メモリ不足）」「（届く敵なし）」）
         ・行をクリック → その武器を装備して対象選択へ
    → 【対象選択】その武器で攻撃できる敵が赤
         ・敵にホバー → 右上に敵ユニット情報・盤上の隅に戦闘予測
         ・敵をクリック → その場で攻撃 → 行動終了（「実行」の確認は無い）
  ```

  「持ち物」で持ち替えてから攻撃するのと結果は同じ（持ち替えは行動を消費しない既存合意のまま）だが、
  メニューを2往復せずに済む＝特効武器の持ち替え忘れを無くすのが目的
- **武器が1本でも一覧は必ず出す**（作者合意）＝どの武器で戦うのかを毎回目にする形。
  一覧はユニットの右隣（画面の右端では左隣へ回り込む）。行は**武器名だけ**（装備中の武器には「（装備中）」）
- **武器を選んだ時点で装備が切り替わる**（作者合意・FE準拠）。
  この後キャンセルしても**その武器を装備したまま**＝既存の「装備変更に取り消しは無い」合意どおり。
  行動は消費していないので、そのまま別のコマンド（待機・持ち物など）へ進んでよい。
  攻撃の後もその武器のまま＝**敵フェイズもその武器で受ける**（三すくみ・挟撃の資格が変わる）
- **武器の行にホバーすると、その武器で狙える敵を盤面に赤く出す**（作者合意）。
  相手を先に選べなくなったぶんの埋め合わせで、どの武器で誰に届くのかをここで見せる。
  塗り直すのは行が変わったときだけ（IMGUI は毎フレーム呼ばれるので毎回引き直さない）
- **押せるかどうかは武器ごとに決まる＝その武器で狙える敵が1体でもいるか**（相手はまだ決まっていないため）。
  灰色の理由は「メモリ不足」（2026-10-24。必殺技なら1本＋消費で判定）／それ以外は「届く敵なし」
  （以前は射程に敵がいるのに飛翔の相性で戦えない「空中不可」もあったが、2026-10-24 に飛翔ごと撤廃）
- **「攻撃」コマンドが出る条件＝持っている武器のどれかで届く敵がいるか**（装備中の武器基準ではない。作者合意）。
  今のユニットは全員が同じ射程の武器しか持たないので見た目の変化はほぼ無い
  （当時は、飛翔中の相手に対空の特効武器を持っているときに攻撃対象に出るのが主な違いだった。対空は 2026-10-24 に撤廃）。
  移動選択中の赤い攻撃範囲・被ダメ確認の相手も同じく全武器の合算。**敵は装備中の1本だけが候補**（既存合意
  「敵AIは所持品を使わない」に沿う＝敵の行動範囲プレビューの見た目は従来どおり）
- **対象選択中は戦闘予測（盤上の隅）と敵ユニット情報（右上）が同時に出る**（作者合意）。
  当初は両方とも右下だったので縦積みにしていたが、**2026-08-16 にユニット情報が右上・
  戦闘予測が盤上へ移り、積む仕組み（stackAbove）は撤去**した＝いまは場所を取り合わない。
  戦闘予測の1行目には「武器: 斬馬刀（消費4）」＝いまどの武器で殴ろうとしているかとメモリ消費が出る
  （当時は残り耐久。2026-10-24 から次の行に「メモリ 5 → 1」も出る）
- **武器の一覧は他のパネルに被らない位置へ逃がす**（作者要望）。避ける相手は戦闘予測（盤上の隅）と
  ユニット情報（右上）の2枚で、逃がし方は「反対の隣へ回り込む → それでも重なるなら縦にずらす」
  （ItemListMenu.AvoidPanels）。矩形は各パネルが `PanelRect` で公開し（出していなければ Rect.zero＝
  避ける対象から自然に外れる）、BattleController.AvoidPanelRects が窓口として渡す。
  **持ち物・交換のメニューは渡していないので従来どおり**
- **【重要】逃がす位置を決めるのは一覧を開いた最初の1回だけ。開いているあいだは動かさない**
  （2026-08-09 のバグ修正。毎フレーム決め直す作りだと武器を選べなくなる）。
  原因は**右上のユニット情報パネルが盤面のクリックを独自に拾う**こと＝武器の一覧は盤面のマスに重なるので、
  行を押した瞬間に下のマスのユニットが右上に出て（あるいは消えて）パネルの大きさが変わり、
  避ける先が変わって**一覧がユニットの左右に飛ぶ → マウスを離したときには行が別の場所にあり
  クリックが不成立** → 押し直すとまた反対へ飛ぶ、を延々と繰り返す
  （敵が周りに多いほど一覧が敵のマスに重なるので出やすい）。
  位置の確定は最初の Repaint まで待つ（各パネルの `PanelRect` は描いたときの値なので、
  開いた直後の Layout ではまだ今フレームぶんが入っていない）。
  ずらし量だけを覚えて基準位置には毎フレーム足すので、カメラが動いても追従する
