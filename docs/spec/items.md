# 持ち物・交換・杖の仕様

### 所持品（インベントリ）の合意仕様（Phase 22〜24・2026-07-19 作者合意。2026-07-20「持ち物」へ改名・操作を2段階UIに刷新）

- 所持品は UnitData.items（List<ItemData>・上限7 = 定数 InventoryCapacity）。一番上の武器が初期装備。
  items が空なら旧 weapon 欄1つを持っている扱い（新旧共存フォールバック。GetInitialItems / GetInitialWeapon）
- 種類は武器（WeaponData）と道具（ToolData）の2つ。どちらも抽象基底 ItemData（DisplayName のみ・直列化フィールド無し）の子。
  WeaponData の基底を ItemData に差し替えてもクラス名・スクリプトGUIDは不変なので既存アセットは無傷。
  素材（第3の種類）・武器耐久は仕様書どおり見送り（設計だけ拡張に耐える形にしておく。
  武器耐久はのちの 2026-08-03 に入れ、2026-10-24 に撤廃）
- ランタイムは Unit.Items（ItemSlot＝item + 残り回数 UsesLeft）で持ち、装備中の武器は Unit.EquippedWeapon。
  **Unit.Weapon => EquippedWeapon の窓口差し替え**で戦闘・AI・UI が自動追随（全参照が Weapon 窓口経由・Data 直読み禁止が効く）
- 装備の持ち替え・外す（非武装になる）・破棄（捨てる）は**行動を消費しない**（合意(a)。同一行動で持ち替え→攻撃可・移動取り消しでも装備は戻らない）。
  行動メニューの「**持ち物**」コマンド（2026-07-20 に「所持品」から改名）から選ぶ。State は ItemSelect（持ち物リスト）＋
  ItemActionSelect（行動サブメニュー）の**計10状態FSM**。**操作は2段階**: リストの項目をクリックすると、リストと詳細を残したまま
  右隣に必ず2ボタンのサブメニューを出す — 装備中の武器=外す/捨てる、装備可の武器=装備/捨てる、装備不可の武器=装備(灰色)/捨てる、
  道具=使う(満タンは灰色)/捨てる。装備・外すの後はメニューを開き直す（攻撃対象などが新装備で再計算）。項目にホバーすると
  武器（種類・前衛後衛・威力・射程）／道具（効果・使用回数）の性能を**画面右下の定位置**に表示（WeaponType.DisplayName で種類名・
  ItemListMenu が2列＋右下詳細を描く）。救出・引き受けの制限分岐では「持ち物」を出さない（早期 return で自動除外＝既存の制限を維持）
  ※メモリで払えない武器も「装備」は押せる（攻撃に使えないだけ。行には「（メモリ不足）」の目印。2026-10-24）
- 「捨てる」で持ち物を破棄（Unit.DiscardItem）。リストから消え、装備中の武器を捨てたら自動で非武装になる。ランタイム(Items)のみ変更＝
  その戦闘中だけ消え次戦は Initialize で復元・行動消費なし・捨てた後は更新リストへ戻る（空なら行動メニュー）。
  装備不可の武器は「装備」灰色＋「捨てる」（この2点は 2026-07-20 の作者ダイアログ合意）
- 道具（傷薬 Tool_Vulnerary・HP10回復×3）は**使うと行動終了**（合意(b)。装備変更と違い行動を消費）。
  HP満タンにはサブメニューの「使う」が無効（押せない）。効果は使用者自身のHP回復（Unit.UseTool → Unit.Heal で最大HPクランプ・
  残り回数-1・0で所持品から消える）。Heal は杖の回復とも共通の土台
- 敵AIは当面所持品を使わない（初期装備固定〔2026-10-24 から、メモリで払えなくなったときだけ自動で持ち替わる〕・道具なし。「敵は救出系を使わない」と同じ前例。
  Unit.Weapon 窓口で戦闘・AIは自動追随するのでコード変更なし）

### 杖（ライブ）の合意仕様（Phase 25・2026-07-19 作者合意）

- 杖は攻撃できない後衛武器。担い手は新ユニット**味方修道士**（兵種 Class_Monk＝歩兵・移動3・杖のみ。
  現行17体は杖を装備できない）。修道士の所持品は [ライブ, 傷薬]、初期装備＝ライブ
- 「杖」コマンド: 杖を装備し、回復できる相手が射程内にいるとき、攻撃と同じ位置に出る（杖ユニットは
  攻撃できない＝攻撃コマンドとは排他）。回復対象を緑で選び、クリックで回復して**行動終了**（合意(b)）
- 回復量 = **使用者の魔力 + 杖の威力**（合意(c)。ライブは威力10・射程1〜1。修道士 魔力6＋10＝16）。
  最大HPは超えない（Unit.Heal でクランプ）。回復対象＝同陣営・生存・HP満タン未満・射程内
- 範囲の緑表示: 選択時に移動範囲（水色）の外側へ「杖が届くマス」を緑フリンジで表示
  （HighlightKind.HealRange。攻撃フリンジとは排他。BattleController.ComputeHealCells）。回復対象の選択ハイライトも緑。
  杖の射程は攻撃の後衛武器と違い、移動しても縮まない（杖は攻撃ではないため）。
  移動力の範囲にいる仲間のマスは緑ではなく水色（2026-10-28 作者合意。それまでは回復できる仲間が緑で見えていたが、
  「移動力の範囲は水色」の決まりにそろえた。緑は移動の外側だけに残る）
- 可否・回復量の判定は Combat/StaffRules.cs に一元化（CombatRules / RescueRules と同じ方針。
  HasStaffEquipped / TryGetStaffRange / FindHealTargets / HealAmount）。対象選択は既存 State.UnitTargetSelect に
  purpose Heal を追加して再利用（ハイライト色を引数化＝救出系は赤、杖は緑）
- 当時は「飛翔中の味方への杖（StaffRules.CanReach）」と「対空判定から杖を除外（IsAntiAirCapable）」も
  決めていたが、2026-10-24 に飛翔・対空ごと撤廃した（いまは飛行兵にも普通に杖が届く）
- 敵からは「非武装扱い」で不利に殴られる（既存の三すくみルールが Weapon=null 相当で自動成立）
- アセット: W_Live（ライブ）・Unit_Player_Monk（味方修道士 HP17/力1/魔力6/技5/速さ6/守備2/魔防6・初期案）。
  Stage_01 の (7,0) に修道士を配置（味方11体目・y=0 は平地の空きマス）
- ライブはメモリ消費0＝回復回数の制限なし（2026-10-24。フェーズ31〜32 の耐久6と補給は撤廃）

### 交換の合意仕様（フェーズ26〜27・2026-07-26 作者合意）

- 「交換」＝隣接する同陣営ユニットとの持ち物の受け渡し。行動メニューの**「持ち物」の直後・「待機」の直前**に、
  交換できる相手が1体以上いるとき出る。可否判定は Units/ExchangeRules に一元化
  （CombatRules / RescueRules / StaffRules と同じ方針）
- 相手は**隣接4マス（上下左右）の同陣営・盤上のユニット**のみ。斜めは対象外。
  **行動済みの味方も相手にできる**（救出の合意(h)と同じ理屈＝受け取る側は受け身で行動を消費しない）。
  受け取っても相手の行動済みは変わらない
- **格納中の貨物とは交換できない**。運び手を経由して貨物の持ち物に触ることもできない
  （貨物は盤上から外れて隣接マスの占有者にならないので、判定上は自然に除外される）。
  運び手（救出中のユニット）自身との交換は可
- 当時は「飛翔状態が同じ相手同士でのみ交換できる」も条件だったが、2026-10-24 に飛翔ごと撤廃した
  （いまは飛行兵と地上のユニットでも交換できる）
- **交換は行動を消費しない**（作者合意(a)。装備変更・外す・捨てると同じ扱い）。渡した後も同じ行動で
  攻撃・被ダメ確認・杖・道具・持ち物・待機を選べる。FE系の慣例（渡すと行動終了）とは違う方針で、
  「持ち物まわりの操作はすべて消費なしで一貫させる」を作者が選んだ結果。1ターンに何度でも交換できる
  （強すぎると感じたら「交換後は再移動→待機のみ」に絞る余地は残してある＝救出・降ろすと同じ分岐1つ）
- **1個でも動かしたら、その行動は取り消し不能になる**（作者合意(c)。ActionContext.Commit）。
  移動取り消しは交換したマスまでしか戻らず、選択解除もできない（必ず攻撃・待機等で行動を終える）。
  相手の状態を変えてしまう操作は巻き戻せない、という救出系と同じ線引き。
  **1個も動かさずに閉じたときは何も起きていない扱い**（Commit も打たない＝誤操作の救済。合意(d)）
- 移動後に交換できる（隣接判定は移動後の位置）。交換後も、使っていない移動力の範囲で再移動できる
- **双方向・1回の交換で何個でも**動かせる（合意(b)）。品は1つずつクリックで反対側へ移る
- 所持数の上限は既存の UnitData.InventoryCapacity（7）。**いっぱいの相手へは渡せない**
  （渡す側の行が灰色の無効行になり、列の見出しに「※いっぱい（受け取れない）」が出る）。
  相手がいっぱいでも「もらう」方向は可能なので交換画面は開ける（持ち物0個のユニットでも開ける）
- **装備中の武器も渡せる。渡すと自動で非武装になる**（「捨てる」と同じ挙動）。
  結果として非武装になることも許可する（確認ダイアログは出さない＝「外す」と一貫）。
  列の見出しの「装備: なし」でその場で気づける
- **兵種が装備できない武器も渡せる。ただし装備はできない**（「（装備不可）」表示・サブメニューの「装備」は灰色）。
  受け取っても自動装備はしない（装備は「持ち物」から明示的に行う＝「捨てる」で非武装になった後と同じ）
- **道具の残り使用回数（ItemSlot.UsesLeft）はそのまま引き継ぐ**。Unit.TransferItemTo が ItemSlot ごと移す。
  受け側で new ItemSlot を作ると回数が満タンに戻る（＝渡すと回復する裏技になる）ので禁止
- 受け取った側は、そのターンまだ行動していなければ**すぐ使える**（傷薬・杖）。行動済みなら次のターン
- **敵AIは当面交換を使わない**（「敵は救出系を使わない」「敵は所持品を使わない」と同じ前例。EnemyAI は無変更）
- UI: State は ExchangeSelect（**計11状態FSM**）。相手選択は既存 UnitTargetSelect に purpose Exchange を
  足して再利用（候補は赤・情報パネルの見出しは「交換する相手」）。交換画面は ItemListMenu の2列モード
  （左＝自分／右＝相手。列見出しは 名前／HP・持ち物 n／7／装備武器）で、画面右下は品の性能詳細に使うため
  ユニット情報パネルは出さない。持ち物が無い列は「（持ち物なし）」の無効行1つ。
  キャンセルは右クリック/ESC で1段ずつ（交換画面→行動メニュー→移動取り消し）
- **要注意（フェーズ26で入れた既存コードの修正2件）**:
  ① ActionContext.Commit は既定で「移動済み」を解除するが、交換は行動を消費せず確定後もそのまま
  攻撃できるため、解除すると「移動した弓兵が交換すると移動していないことになり、後衛武器の射程が
  2マスちょうど→武器上限まで伸びる」抜け穴になる。交換からは Commit(keepHasMoved: true) で呼ぶ
  （既存3か所＝救出・引き受け・降ろすは既定 false で挙動不変）。
  ② Commit が飛翔の中間点も現在地へ引き上げるようにした（従来は「飛翔→移動→引き受け→取り消し」で
  飛翔した位置まで戻り、使った移動力が復活していた）。※飛翔の中間点は 2026-10-24 に飛翔ごと撤廃
- スコープ外（将来）: 輸送隊への預かり（部隊倉庫）・武器耐久・素材・ショップ・敵AIの交換・
  貨物との交換・まとめ選択。判定を ExchangeRules に、UIを「2つの持ち物を並べて品を移すだけ」に
  保っているので、相手が「預かり枠」や「店の在庫」に変わっても同じ画面を使い回せる
